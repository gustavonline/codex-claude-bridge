# Native custom-provider affinity

Updated 7 November 2026. Source candidate; matching native consumption and Desktop acceptance are separate operator gates.

Codex 0.166 validates a saved thread's provider against the current process selection before resume/input. A successful `thread/start` per-thread override on an OpenAI-selected app-server does not prove that its first turn can run. `turn/start` has no public `modelProvider` override. Upstream: https://github.com/openai/codex/pull/57840 (commit 7ce5fa7bdc1e816cc1306f93dba7dc7bede3a3de).

Bridge keeps native GPT on its original app-server. Custom Responses connections use on-demand stdio children of the same selected official executable, with the same home/environment/permission arguments and additional launch-scoped provider selection/definition. These children explicitly use `--no-daemon`, so they cannot reuse an OpenAI/default-provider daemon. They use native `initialize` / `initialized`, not the MCP lifecycle. This starts no model server, downloads no model and changes no user config or default provider. A bounded child pool ends with Bridge; unexpected exit/init refusal is retained, never retried on GPT.

The existing exact-thread route sidecar determines connection/model. On a new child, the same thread is resumed and its identity/path/ancestry verified before input. Explicit cross-provider/model overrides and alternate history/path remain refused. Hiding a model is unrelated to affinity. The router does not rewrite transcripts, change native provider policy or copy auth. Native structured provider errors retain their public error data rather than being mislabeled as authentication or backend inference failure.

Explicit caller Retry is a new caller operation with one dispatch; Bridge never automatically repeats a failed turn. Custom queue add/start remain unqualified/refused. Existing readable-history/native-GPT paths and Claude execution remain separate. An in-memory stdio seam verifies launch arguments, handshake, lifecycle and public errors, not OS/native execution. A matching 0.166 synthetic listener trial was REFUSED in the worker sandbox (`listen EPERM 127.0.0.1`) before Codex spawned. Root's separately authorized finite operator proof must establish first turn, Retry, same-thread resume/restart and history; actual Mac/owner delivery remains unqualified until then.

Unified slots and browser authentication are subsequent source work, not features supplied by this repair. No real key enrollment, OpenRouter free-model qualification, normal-profile activation or public release is claimed here.

Root operator R1 on frozen 4846cba reproduced the actual 0.166 mismatch before any synthetic inference and successfully initialized the launch-selected child (both children exited 0). Resuming the empty failed baseline thread then returned `no rollout found`: its first turn had been refused before native persisted a rollout. This does not prove persisted-thread recovery is broken or that empty-thread history can be invented. The next operator trial creates a NEW thread directly in the selected child, persists actual synthetic turns, then checks Retry/resume/restart/fork. Original failed empty chats/messages stay untouched; no automatic resend, ID rewrite or rollout creation is supplied by Bridge.

Independent GPT review of 4846cba requested two source repairs: auto-resume must take the caller thread ID for legacy v1 sidecars (which have no threadId member), and saved-history reads must remain on the native parent independently of failed execution children. Both are covered by focused regressions in the follow-up candidate; the old review remains CHANGES REQUESTED on its original bytes.
