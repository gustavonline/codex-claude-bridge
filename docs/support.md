# Support and acceptance

This is an MVP preview, not full Codex parity. Checks are intentionally divided into deterministic backend contracts, real runtime integration and observed desktop behavior.

In synthetic checks the bridge announces and lists it during that interval in the shape of the installed Codex queue schema; the desktop's actual list responses were not captured. On RC9 a correction sent during a long counting answer was answered after the count finished, in the same turn. Immediate interruption of an answer in progress is not supported or qualified. Repeated IDs return the accepted turn. Stop does not undo a tool already dispatched. Visual controls still need checking. |
| Fork | Independent native ID and retained prefix tested with real models, including a fork while Claude or GPT is running. An unbounded fork keeps only finished turns; explicitly including an active turn is rejected. No ephemeral/prediction fork or alternative history source. |
| Archive/unarchive | Active Claude self-archive, retained final history and paused queue tested with the official runtime. Native GPT archiving may interrupt its active turn. A local self-archive uses the public thread lifecycle after tool discovery and approval, because archiving closes its own MCP transport. Final history remains available on reopen; archived updates are not sent to the detached renderer. Unarchive before starting a new or queued turn; retries of an already delivered message still return its receipt. Unarchiving an idle chat preserves queued messages for deliberate continuation. On RC7 the owner saw a false “Failed to unarchive” toast after a successful unarchive. Its log shows two overlapping resumes with the second rejected as busy; their parameters were not captured, so the toast's cause is unproven. Identical concurrent resumes now share one native resume, while different requests still wait. On RC9 the owner confirmed ordinary unarchive works, but Undo on the archive notice still shows “Failed to unarchive conversation”. The three unarchive calls in that session all completed, but none is linked to the failing notice, so the cause is not yet identified. |

| Session coordination | Canonical reads, send, queue, wait, interrupt and fork tested. Real Claude read/send/wait and GPT dynamic-tool read exercised. Same workspace/profile and matching permissions only. |
| Concurrent histories | Six independent synthetic chats, 108 completed turns, bounded pagination and restart tested. This is not proof of very large model context or macOS sleep recovery. |
| Browser/editor panels | Native signed helpers work and user confirmed browser/editor opening in an earlier isolated build. New builds still need a short visual smoke test. ## Explicitly unsupported or unqualified

Explicit compaction, native review/rollback/deletion, exact Claude quota/context-meter parity, arbitrary Fast/service tiers, voice/realtime, goals, automation and cloud/remote orchestration are not implemented as full Claude equivalents. Relevant turn-mutating routes fail explicitly. Native sharing, export and global search are not qualified for complete Claude history.

Old prototype chats may retain native prompt copies from before clean tool-host seeding. Fork them before relying on removal of old context after editing. A complete OpenPencil workflow, cross-chat panel placement, macOS sleep recovery and very long SDK compaction sessions remain acceptance work.

## Reproduce

`npm run check` runs synthetic tests without model credentials. `node scripts/live-test.mjs --run --copy-codex-auth` opts into real Claude/Codex usage and temporary Codex-login copies using disposable private local state. `--scenario native` isolates native session-tool and restart checks; `--scenario steering` tests direct and queued steering during a synthetic tool call, then retries and memory after restart. `--scenario lifecycle` forks an active Claude/GPT chat, exercises self-archive/unarchive and its paused queue, then checks the child's model handoff and restart memory. `codex-claude check` copies no Codex auth file, sends no model prompt and checks installed protocol/catalog compatibility.

Session management under interactive approval policies asks in the desktop; `never` is explicit noninteractive delegation within matching workspace/permission boundaries. Shell calls under `untrusted`/`on-failure` conservatively ask before execution. Unknown or granular prompt policies are not mapped and fail explicitly; there is no permission escalation.

Raw local evidence and conversations are not distributed. CI results are attached to exact GitHub revisions; reviewed release notes record runtime versions and outstanding limits. A passing mock is never presented as a live or visual result.

## Short desktop check

1. In a new managed Claude chat, open a URL and a local text file. Confirm both appear in that chat's side panel.
2. During a longer answer, send a correction directly, then promote a queued message. Confirm both appear in the same active turn. Stop another turn and resume deliberately; confirm remaining queued messages are preserved.
3. Fork that chat, switch the child to GPT and back, and confirm retained memory and model feedback. Confirm panels open in the selected child.

These are visual checks. Model memory, delivery deduplication and backend queue contracts are already covered automatically.
