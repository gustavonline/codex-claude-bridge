# Home browser connections and shared model slots

Source increment, 7 November 2026; based on the accepted5df09d0 affinity repair. No normal-profile activation or public release.

## Human flow

Open **Model Bridge** directly through its existing global/thread entrypoint. The default plugin remains unbound/read-only. The explicit provider binding supplies one fixed private store/profile; UI requests cannot choose paths, programs or another profile. Open the gear → Connect OpenRouter → Open browser → authorize → Home observes the saved connection automatically → Refresh its catalog → return to the model library → add eligible models to square slots → Save. Already saved OpenRouter connections display their durable connected/disconnected state rather than repeating sign-in. Browser opening uses the public MCP Apps `ui/open-link` capability; if the host does not advertise it, that action stays unavailable. Native Codex sign-in remains in Codex; Claude uses its existing official runtime/login.

The existing launch-scoped custom-provider child uses the official native app-server and `--no-daemon`. No model API proxy, global `model_provider`/`base_url` edit or automatic service/model startup is introduced. Custom cross-provider switching requires a new thread; custom queued admission remains unqualified/refused. The empty thread rejected by native affinity before its first turn may have no rollout to resume; no IDs, histories or failed queued messages are rewritten or replayed.

## Home layout and state updates

Chosen square slots sit above one complete model library, searchable by model/connection name and filterable by connection and availability/slot membership. The gear opens connection settings; defaults and reset/clear are secondary disclosures. Save appears for a draft, an initial uncured selection or a pending save. The canonical design and 36-view flow inventory are in [design.md](../design.md).

Home reads the declared registry on open, every ten seconds while visible and every second during a pending browser sign-in. These are read-only local status requests, never implicit catalog HTTP or inference. Unchanged replies do not rebuild controls or disturb focus. A mutation supersedes an earlier background read. Drafts survive readback, a concurrent slot revision surfaces a choice, and an uncertain write is recovered by a correlated same-scope status read without replay. A failed read pauses automatic retries and exposes Retry. Endpoint/auth/catalog errors stay concise and actionable after recovery.

## Auth boundary

The fixed OpenRouter browser flow follows https://openrouter.ai/docs/guides/overview/auth/oauth: S256, random verifier/state, exact127.0.0.1 ephemeral callback, three-minute lifetime, one consumed callback, explicit cancel/expiry/process-end cleanup. Only the fixed HTTPS authorization/exchange origins are used; no redirects, arbitrary executable helper, token argument, env-key fallback or key paste. Verifier/code/key stay in the local backend. The native OS item and reference both bind the exact canonical endpoint; edits or redirects cannot reuse another endpoint's credential. JSON holds references only. Disabling a connection or hiding a model never deletes its credential.

macOS uses fixed Keychain Services through the packaged os-secret.py and a guarded regular Python executable (`BRIDGE_PYTHON`, otherwise system `/usr/bin/python3`). The launcher must supply the selected environment consistently to Home and Bridge; Root will explicitly set `/usr/bin/python3`. Linux uses fixed `/usr/bin/secret-tool`; metadata availability does not prove a working Secret Service session. Native helper errors are sanitized. Same-UID/full-access model tools are **not** claimed to be isolated from the credential helper or OS store; actual host sandbox/access qualification remains required before live credentials. There is no custom vault or credential copy from Factory/normal accounts.

Catalog wire reads are bounded at2MiB/1024 unique actual IDs; normalized provider state is separately bounded at4MiB before atomic publication and on read, including the observed460-model OpenRouter shape. OpenRouter connections are effectively free-only, including legacy records without the optional field and the generic form at that exact base URL; no silent file migration is required. Only explicit zero prices in every supplied price field qualify; missing/paid prices, stale catalogs and credential failures fail closed without a paid fallback. All460 IDs may be shown, but ineligible models cannot be added/admitted. Advertised parameters and generic IDs do not establish Codex capabilities or actual billing. Other compatible endpoints have no invented free/capability promise. Auth, rate limit, unsupported catalog and unreachable errors remain distinct. Failed refresh retains prior identities/selection as stale.
