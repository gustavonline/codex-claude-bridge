---
name: setup
description: Install the local Model Bridge for Codex, verify official Claude subscription login, and prepare the launcher that opens your normal Codex app with Claude (or the separate test window).
---

Use this plugin's version-pinned [installer](../../install.command). Resolve its absolute path from this skill's location. It verifies the adjacent npm archive or retrieves the exact pinned GitHub release using existing GitHub access, then installs the package under `~/.local/share/codex-claude-bridge`, checks Claude, and creates two launchers: `~/Applications/Codex + Claude (main app).command` for the normal Codex app and `~/Applications/Codex + Claude.command` for the separate test window. It opens neither. The CLI executable is `~/.local/share/codex-claude-bridge/node_modules/.bin/codex-claude`; do not rely on PATH.

Before installation, check macOS, Node >=22, Python >=3.11 and the installed Codex desktop. Reuse existing installations. If a prerequisite is missing, install it with the existing package manager within the user's installation request; do not install a new package manager as a side effect. The installer uses Anthropic's official native installer only when Claude Code is absent. Login uses `claude auth login`; the person completes that login. Never extract, copy or proxy Claude credentials. Do not print raw auth status, which includes account details.

For an existing bridge installation, run `codex-claude status --json` and `codex-claude primary status --json` and preserve its profile. An upgrade replaces the installed package only after both the separate test window is idle and stopped and no Bridge from that package runs. Codex opened with the main-app launcher must have been quit by the person once its chats are idle; the installer checks this and refuses otherwise or when it cannot tell. Never quit, restart or relaunch Codex yourself, and do not run the installer from a chat in Codex opened with the main-app launcher, because that Codex is still running. If adopting a known earlier prototype, pass `--state <existing-profile>` to the installer.

Run the bundled installer with the selected path options. It checks subscription authentication and runtime compatibility and prepares the launchers; it opens no app. Claude in the normal Codex app needs one deliberate relaunch by the person: when all chats are idle, they quit Codex and open `Codex + Claude (main app)`, or run `codex-claude primary`. The launcher refuses while Codex runs. It opens the unchanged, code-signed app with its normal profile through macOS and gives only that launch the Bridge as its app-server. It copies no profile, auth or configuration. A normal Dock launch stays GPT-only; to return to GPT-only Codex, the person quits it once its chats are idle and opens it normally. No HTTP model endpoint or background daemon is required; the adapter runs on stdio and exits with the app.

Then read `codex-claude doctor` and the saved compatibility report. They are preflight checks that copy no credentials and send no model prompt: the compatibility check uses a temporary separate profile and public protocol calls to confirm both model catalogs and the native and Claude thread routes, and doctor gives a content-free diagnosis including Claude login. They do not open or require either window, and they do not show Claude active in the main app. `codex-claude primary status` separately reports whether this installation's current Bridge is active in Codex opened with the main-app launcher for the selected app (unknown when its evidence cannot be confirmed). Neither shows that Claude, tools, files, the browser or OPD work there; that needs separate acceptance. Main-app chats and logs are under `<state>/primary`; `doctor` and `logs` read the separate window's state. Login does not prove remaining quota. Protocol checks do not prove that a browser/editor panel was displayed. Do not send test prompts into existing user chats.

Removing this skills plugin does not uninstall the separate CLI or delete chats. Stop the idle isolated app with the CLI if requested; preserve its state unless the user asks to remove it.
